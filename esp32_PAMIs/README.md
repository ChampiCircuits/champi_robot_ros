# ESP32 PAMIs

This folder contains the full toolchain used to configure and run PAMIs (small autonomous robots) on ESP32 boards:

- a shared ESP32 firmware project (`firmware/`)
- a web configurator (`pami_web_configurator/`) to edit trajectories, simulate interactions, generate C++ trajectory headers, and trigger build/flash

## What The System Does

1. Edit per-PAMI trajectories on a 3000 mm x 2000 mm table map.
2. Preview timeline-based motion for multiple PAMIs.
3. Save project config to `pami_web_configurator/backend/data/config.json`.
4. Generate `firmware/include/generated_trajectory.h` for a selected PAMI.
5. Build and flash firmware through PlatformIO.

## Prerequisites

- Linux or Windows
- `python3` (Linux) or `python` (Windows)
- `npm` (Node.js)
- Python packages: `fastapi`, `uvicorn`, `platformio`
- USB access to ESP32 board

Example backend install:

```bash
python3 -m pip install fastapi uvicorn platformio
```

Install frontend dependencies:

```bash
cd pami_web_configurator/frontend
npm install
```

## Quick Start (Web Configurator)

### Linux

From `pami_web_configurator/`:

```bash
npm run dev
```

This runs `start_pami_configurator_linux.sh`, which starts:

- backend on `http://localhost:8000`
- frontend on `http://localhost:5173`

### Windows (PowerShell)

From `pami_web_configurator/`:

```powershell
npm run dev:windows
```

This runs `start_pami_configurator_windows.ps1`, which starts:

- backend on `http://localhost:8000`
- frontend on `http://localhost:5173`

Open `http://localhost:5173` in your browser.

## Typical Workflow

1. Select a PAMI ID (1..6).
2. Click on the table to add waypoints.
3. Use timeline controls to preview motion and potential collisions.
4. Set global speed (cm/s) and start delay (s).
5. Save the project config.
6. Connect a target ESP32 by USB.
7. Click `Compiler & Flasher` for the selected PAMI.

The backend then:

- loads the saved config
- generates `generated_trajectory.h` for that PAMI
- runs `python3 -m platformio run --target upload` in `firmware/`

## Firmware Notes

Main entrypoints:

- `firmware/src/main.cpp`: initialization and periodic tick
- `firmware/src/motion.cpp`: motion state machine, trajectory execution, team mirroring, obstacle gating

Current runtime behavior includes:

- waiting for tirette start event
- applying `DELAY_AFTER_PULL_CORD_S` before motion
- team switch handling (blue/yellow)
- yellow team trajectory mirroring on X axis (`x = 3000 - x`)
- HC-SR04 pause/resume logic with hysteresis (`OBSTACLE_STOP_MM`, `OBSTACLE_RESUME_MM`)
- stepper wheel commands through `stepper_control`
- periodic serial telemetry at 115200 baud

Tune hardware and motion constants in `firmware/include/config.h`.

## Manual Firmware Commands

Build:

```bash
python3 -m platformio run -d firmware
```

Flash:

```bash
python3 -m platformio run -d firmware -t upload
```

Serial monitor:

```bash
python3 -m platformio device monitor -d firmware -b 115200
```

## API (Backend)

- `GET /api/config`: load saved config (or defaults)
- `POST /api/config`: save trajectories/speed/delay
- `POST /api/flash/{pami_id}`: generate header + build + upload

## Troubleshooting

- `python3: No module named uvicorn`:
  install backend Python dependencies.
- `npm: command not found`:
  install Node.js and npm.
- flash/upload failure:
  check USB cable, board connection, and serial permissions.
- frontend cannot reach backend:
  ensure backend is running on port `8000` and not blocked by firewall.

## Important Generated File

`firmware/include/generated_trajectory.h` is generated by the backend.
Do not manually edit it in normal usage.
